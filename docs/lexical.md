# 字句のこまごました決めごと

文字列リテラルと行コメントの扱い。
**通常コードとノベル DSL の両方**に関わる。

biwa には字句解析が 2 つある。

| どこ                                         | 何を読むか                        |
| -------------------------------------------- | --------------------------------- |
| `biwac_lexer`                                | 通常の `.biwa` コード             |
| `biwac_novel_parser` (`token.rs`, `scan.rs`) | `scene {{ .. }}` の中のノベル DSL |

**同じ文字列は両方で同じ意味にならなければならない。**
そのため、エスケープの対応表は `biwac_base` (`escape.rs`) に 1 つだけ置き、
両方がそれを使う。

## 文字列リテラルのエスケープ

| 書き方 | 意味 |
| ------ | ---- |
| `\"`   | `"`  |
| `\\`   | `\`  |
| `\n`   | 改行 |
| `\t`   | タブ |
| `\r`   | 復帰 |

**どの言語でも同じ書き方・同じ意味になるものだけを入れてある。**
biwa が独自に決める余地の無いものだけ、という基準である。

入れていないものと、その理由。

- `\u{..}` / `\uXXXX` / `\U........` — **言語ごとに書き方が割れる**
  (Rust は `\u{1F600}`、JS と Java は `😀`、Python は `\U0001F600`)。
  どれにするかを決めてから入れる
- `\'` — **要らない**。biwa の文字列は必ず `"` で囲むので、
  `'` はエスケープせずそのまま書けばよい
- `\0` / `\b` / `\f` / `\v` — 上の 5 つほど普遍ではない。
  ノベルゲームで要る場面も思いつかない

### 知らないエスケープはエラーにする

```
Error: unknown escape `\u` in a string literal
     ╭─[ main.biwa:197:19 ]
     │
 197 │   greeter::greet("\u{1F600}")
     │                   ─┬
     │                    ╰── not an escape
     │
     │ Note: biwa understands `\"`, `\\`, `\n`, `\t`, `\r`; write `\\` for a backslash itself
─────╯
```

黙って `\` を残す手もあるが、そうすると**あとから足せなくなる**。
`"\u{1F600}"` がいま `\u{1F600}` という 9 文字として通ってしまうと、
`\u` を入れた日に既存のコードの意味が変わる。
エラーにしておけば、増やすのはいつでも安全である。

## 行コメントと文字列

`//` から行末までがコメントである。**ただし文字列の中は別**である。

```biwa
let url = "https://example.com";  // ここからがコメント
```

最初に現れた `//` で切ると `https:` の後ろで割れる。
行を頭から走査して、いまコードの中に居るのか文字列の中に居るのかを
見分ける必要がある。

```text
                   ┌──`\`──> エスケープ ──┐
                   │                      │
    ┌──────`"`──> 文字列 <────────────────┘
  コード <────`"`──┘
    │
    └──`//`──> コメント (行末まで)
```

エスケープの状態を持たないと `"a\"// b"` で閉じ位置を間違える。

## ノベル DSL ではもう 1 つ外側がある

生ノベルテキストの中では、**`"` も `//` もただの文字**である。

```biwa
scene foo(g: MyGame) -> MyGame {{
    彼は "そうだ" と言った        // ← `"` は文字列を開かない。`//` はコメント
    $gray("// コメントも書けるよ") // ← この `//` はコメントではない
}}
```

コードとして読まれるのは `$` の埋め込み式の中だけなので、
走査はこうなる。

```text
  地の文 ──`$`──> 埋め込み式 (= 上の 4 状態) ──式の終わり──> 地の文
    │
    └──`//`──> コメント (行末まで)
```

どこまでが埋め込み式かは、文法が
**「必ず `)` で終わる」**ことを使って測る (`docs/content-api.md` の 1 節)。
つまり行コメントの切り出しと埋め込み式の範囲測定は、
同じ 1 回の走査の途中経過でしかない。
2 箇所に分けて書くと必ず食い違うので、`biwac_novel_parser/src/scan.rs` に集めてある。

埋め込み式が壊れている行では、コメントを探すのをそこでやめる。
形の誤りは本文を読むときに span 付きで報告されるので、
走査の側でも報告すると同じ誤りが 2 回出る。

### 生テキストの `\`

生テキストの中では `\$` だけがエスケープで、`$` そのものを表す。
それ以外の `\x` は `\x` としてそのまま出る。

文字列リテラルと違って**未知のエスケープをエラーにしていない**のは、
地の文はほとんどが自然言語で、`\` が記号として出てくることがあるためである。
